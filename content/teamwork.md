# همکاری تیمی و مشارکت

قرارداد API را از روز اول با Frontend توافق کنید. هر قابلیت کوچک پس از تکمیل در اختیار تیم قرار گیرد؛ اتصال را به روز آخر موکول نکنید. اعضای محصول با اعضای تیم هکاتون متفاوت‌اند.

## روند روزانه

1. Issue شامل رفتار، ورودی و خروجی و معیار پذیرش بنویسید.
2. برنچ مستقل مانند feature/transactions بسازید.
3. تغییر کوچک و قابل مرور ثبت کنید؛ قرارداد و migration را همراه کد به‌روز کنید.
4. PR شامل مسئله، رفتار جدید، روش بررسی و محدودیت‌ها باشد.
5. هم‌تیمی تغییر را مرور و CI را بررسی کند؛ بعد از موفقیت ادغام کنید.

## تعریف انجام‌شدن

API از دیتابیس واقعی داده می‌خواند؛ حالت موفق و خطا و دسترسی کنترل شده؛ Swagger به‌روز است؛ Frontend قابلیت را مصرف می‌کند؛ migration و seed قابل اجرا هستند؛ تصمیم و محدودیت مستند است.

## قرارداد همکاری Frontend

روی فیلدها، Enumها، رشته decimal، UTC، صفحه‌بندی، فیلتر، token و انتخاب Workspace توافق کنید. برای Loading و Empty و Error و 401 و 403 و 409 رفتار مشخص داشته باشید. mock با داده برچسب‌خورده تنها تا اتصال API استفاده شود.

## کمک گرفتن و گزارش اشکال

برای سؤال از Issue استفاده کنید: بخش سناریو، انتظار، رفتار فعلی، مراحل بازتولید و خروجی پاک‌سازی‌شده را بنویسید. password و token و connection string نفرستید. استفاده از منابع و ابزارهای کمکی باید با توانایی توضیح و نگهداری خروجی همراه باشد؛ سیاست رسمی برگزارکننده در صورت اعلام اولویت دارد.
