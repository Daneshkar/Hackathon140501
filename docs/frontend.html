راهنمای فرانت‌اند هکاتون

دانلود دفترچهٔ اصلی (PDF) فایل کامل فیگما ↗ قرارداد API

از طرح‌های فیگما یک رابط قابل استفاده بسازید و دادهٔ صفحات را با قرارداد API هکاتون هماهنگ کنید. دامنهٔ تحویل شامل ۹ صفحه در حالت روشن و تیره است. انتخاب فریم‌ورک و کتابخانه با تیم است و TypeScript قویاً توصیه می‌شود.

مسیر پیشنهادی پیاده‌سازی

  1. شناخت طراحی و قراردادها. مسیرهای عمومی و محافظت‌شده، دادهٔ هر صفحه و نیاز به احراز هویت را مشخص کنید. پیش‌نیازها، دستور اجرا و متغیرهای محیطی را در README ثبت کنید.
  2. ساخت پایهٔ رابط و تم. رنگ، تایپوگرافی و فاصله‌ها را از فیگما استخراج کنید و اجزای مشترک مثل دکمه، ورودی، جدول و مودال را بسازید. هر دو تم را در اندازه‌های مختلف صفحه بررسی کنید.
  3. ساخت جریان ورود و پوستهٔ پنل. ثبت‌نام، ورود، مدیریت نشست و مسیرهای محافظت‌شده را پیاده کنید. ناوبری مشترک پنل را برای استفاده در صفحات داخلی آماده کنید.
  4. اتصال صفحات به داده. داشبورد و نمودارهای مشخص‌شده، بازارها، دارایی‌ها، تراکنش‌ها، افراد و تنظیمات را به APIهای مربوط وصل کنید. صفحهٔ اصلی را طبق فریم خودش بسازید.
  5. آزمون و آماده‌سازی تحویل. حالت‌های بارگذاری، داده، خالی و خطا، اعتبارسنجی فرم‌ها، نقش‌ها و واکنش‌گرایی را بررسی کنید. در پایان پروژه را طبق README از یک محیط تازه نصب و اجرا کنید.

تیم می‌تواند ترتیب این مراحل را با توجه به برنامهٔ خودش انتخاب کند.

امتیاز ویژه و شواهد عملکرد

جدول دفترچه حداکثر ۳۰ امتیاز ویژه ثبت کرده است. سقف بهبود عملکرد ۱۵ امتیاز و سقف الگوهای طراحی ۱۵ امتیاز است. متن همان بخش از شش محورِ حداکثر ۵ امتیازی نام می‌برد. جزئیات تقسیم امتیاز ویژه نیازمند تأیید برگزارکننده است.

برای امتیاز عملکرد، روی نسخهٔ قابل تحویل در شرایط یکسان، ابزار، دستگاه یا شرایط آزمون و نتیجه را ثبت کنید. دفترچه از Core Web Vitals برای سنجش بارگذاری محتوای اصلی، پاسخ‌گویی به تعامل و ثبات چیدمان استفاده می‌کند. امتیاز ویژه به بهبود اجراشده و قابل نمایش تعلق می‌گیرد.

راهنمای فنی و انتخاب ابزار

  • وضعیت محلی رابط و دادهٔ دریافتی از سرور را جدا نگه دارید. تایپ ورودی کامپوننت‌ها و پاسخ‌های API به خوانایی مسیر داده کمک می‌کند.
  • خطای فرم را نزدیک فیلد نشان دهید و هنگام ارسال از درخواست تکراری جلوگیری کنید. قواعد مقدار و اعشار ورودی مالی را از قرارداد API بگیرید.
  • گزینه‌های نامجاز را متناسب با نقش کاربر مدیریت کنید. بررسی مجوز عملیات در سمت سرور انجام می‌شود.
  • دفترچه برای رابط React با Vite یا Next.js، برای دادهٔ سرور TanStack Query یا RTK Query، برای فرم React Hook Form همراه Zod یا Yup و برای نمودار Recharts، ECharts یا Chart.js را پیشنهاد می‌کند. تیم می‌تواند از ابزار متناسب با پروژهٔ خودش استفاده کند.

چک‌لیست تحویل

  • لینک مخزن Git و شاخه یا نسخهٔ نهایی مورد داوری.
  • README.md شامل پیش‌نیازها، دستور نصب و اجرا، روش آزمون و متغیرهای محیطی.
  • .env.example با مقادیر نمونه و بدون اطلاعات محرمانه.
  • نشانی API یا روش Mock، همراه توضیح دسترسی و داده‌های آزمایشی.
  • لینک نسخهٔ آنلاین، در صورت وجود، در کنار کد قابل اجرا.
  • دستور بازتولید بخش‌های وابسته به سرویس بیرونی در README. اطلاعات ورود آزمایشی را از کانال مورد تأیید برگزارکننده ارائه کنید.
